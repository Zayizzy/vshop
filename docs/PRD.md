## 1. 产品概述

### 1.1 产品定位

一款聚焦本地服务、深耕私域流量的生鲜商城微信小程序。整合本地多供应链资源，以次日达为履约标准，通过"包裹卡片引流 + KOC社交分销"双引擎驱动获客增长。

### 1.2 产品目标

| 维度 | 目标 |
|------|------|
| 用户价值 | 次日达新鲜到家，源头好货直供 |
| 商家价值 | 多供应链并行入驻，零库存轻资产运营 |
| 平台价值 | 私域流量闭环，KOC分销裂变，渠道数据全追踪 |
| 技术目标 | 订单路由自动化，WMS双向同步，渠道归因100%覆盖 |

### 1.3 目标用户

| 用户群 | 特征 | 消费场景 |
|--------|------|---------|
| 家庭采购主理人 | 25-45岁女性为主，关注品质和时效 | 家庭食材日常采购 |
| 社区拼单用户 | 社群活跃用户，受KOC推荐驱动 | 跟团购买、社交拼单 |
| 礼品采购用户 | 季节性需求，产地直发 | 送礼、节日采购 |

## 2. 商业模式

### 2.1 获客模型

```
┌─────────────────┐     ┌──────────────────────────────────┐
│  包裹卡片引流     │     │        KOC社交分销               │
│                  │     │                                  │
│ 快递包裹附带卡片   │     │ KOC入驻 → 推广链接/码生成         │
│ ├ 小程序码        │     │    ↓                            │
│ ├ 短链            │     │ 朋友圈/短视频/社群 一键分享        │
│ └ 渠道溯源参数     │     │    ↓                            │
│                  │     │ 曝光 → 点击 → 转化 → 订单 → GMV    │
│ 独立渠道数据看板   │     │    ↓                            │
└─────────────────┘     │ 自动分佣结算                        │
                        └──────────────────────────────────┘
```

#### 包裹卡片引流能力

| 能力 | 说明 |
|------|------|
| 小程序码生成 | 动态生成带渠道参数的小程序码 |
| 短链生成 | 支持微信URL Scheme短链，可追踪 |
| 渠道溯源 | UTM参数体系，区分卡片来源、批次、区域 |
| 数据看板 | 卡片扫码量、进入量、转化率、GMV |

#### KOC分销能力

| 能力 | 说明 |
|------|------|
| KOC入驻 | 微信授权，提交资料，平台审核 |
| 推广码/链接 | 唯一KOC标识，自动追踪 |
| 物料生成 | 小程序码 + 海报 + 文案模板 |
| 一键分享 | 朋友圈、社群、短视频平台 |
| 全链路追踪 | 曝光、点击、加购、下单、支付、GMV |
| 佣金结算 | 按等级分佣，T+N自动结算到微信零钱 |

### 2.2 履约模型

```
用户下单 → 平台接单 → 订单路由引擎（按商品/区域/库存/价格）
                         ↓
              供应商A    供应商B    供应商C
                ↓          ↓          ↓
              拣货打包    拣货打包   拣货打包
                ↓          ↓          ↓
              供应商直接发货（次日达）
                ↓
          第三方WMS打单系统
          （店管家 / 聚水潭）
          打单 → 拣货确认 → 出库
                ↓
          物流轨迹回传 → 用户端查物流 → 签收
```

#### 履约规则

| 规则项 | 说明 |
|--------|------|
| 配送时效 | 当日截单前下单 → 次日达；截单后 → 顺延一天 |
| 截单时间 | 每日 20:00（可配置） |
| 发货主体 | 供应商直接发货，无需平台中转 |
| 多包裹 | 不同供应商商品分包裹发货，独立物流 |
| 配送范围 | 按供应商服务区域配置 |

### 2.3 供应链模型

```
多供应链并行入驻

── 供应商A：区域A，品类A，价格策略A
── 供应商B：区域B，品类B，价格策略B
── 供应商C：区域C，品类C，价格策略C

订单路由引擎：
├── 按商品分配：商品A → 供应商A
├── 按区域分配：同商品不同区域走不同供应商
├── 按库存分配：主供缺货切备供
└── 按价格分配：同品多供比价择优

订单全量同步至第三方WMS
├── 店管家：打单、拣货、发货
└── 聚水潭：同上，支持多WMS并行
```

## 9. 订单路由引擎

### 9.1 路由规则

| 规则类型 | 优先级 | 说明 |
|----------|--------|------|
| 按商品分配 | P0 | 商品与供应商绑定关系，订单按商品拆分路由 |
| 按区域分配 | P0 | 同一商品在不同区域可配置不同供应商 |
| 按库存分配 | P0 | 主供应商库存不足时自动切换备用供应商 |
| 按价格分配 | P1 | 同品多供时，优先分配价格最优供应商 |
| 按负载分配 | P2 | 根据供应商履约能力动态分配 |

### 9.2 路由流程

```
订单生成
  │
  ├── 1. 按商品拆分子订单
  │
  ├── 2. 对每个子订单：
  │     ├── 查找该商品绑定的供应商列表
  │     ├── 按区域过滤（收货地址在供应商服务范围内）
  │     ├── 按库存过滤（有库存的供应商）
  │     └── 按优先级排序（主供 > 备供）
  │
  ├── 3. 分配确认
  │     └── 主供有货 → 分配主供
  │     └── 主供缺货 → 分配备供 → 平台预警
  │     └── 全部缺货 → 订单异常 → 人工介入
  │
  └── 4. 推送至对应供应商 + 同步WMS
```

### 9.3 异常处理

| 异常场景 | 处理方式 |
|----------|---------|
| 全部供应商缺货 | 订单标记异常，通知运营，通知用户 |
| 供应商不在服务范围 | 不可下单，前端提示 |
| WMS同步失败 | 重试3次，失败后转为手动处理 |
| 部分商品路由失败 | 成功部分正常流转，失败部分标记异常 |

## 10. 第三方系统对接

### 10.1 店管家 WMS

| 功能 | 方向 | 说明 |
|------|------|------|
| 订单推送 | 平台 → WMS | 订单确认后自动推送 |
| 打单状态 | WMS → 平台 | 已打单/待拣货 |
| 拣货状态 | WMS → 平台 | 拣货完成 |
| 出库回传 | WMS → 平台 | 已发货 + 快递单号 + 物流公司 |
| 库存同步 | WMS → 平台 | 实时/定时库存数据 |
| 退货入库 | WMS → 平台 | 退货签收入库 |

### 10.2 聚水潭 WMS

同店管家对接能力，支持按供应商维度配置使用哪个WMS系统。

### 10.3 订单状态机（平台 ↔ WMS双向同步）

```
待支付 → 已支付 → [推送WMS] → 已打单 → 已拣货 → 已出库 → 运输中 → 已签收
                                    ↓         ↓        ↓         ↓
                                  WMS回传  WMS回传   WMS回传   物流回传
```
