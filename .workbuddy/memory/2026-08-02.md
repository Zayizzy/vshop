## 修复下单 500：OrderItem.image 列过短（VARCHAR(191)）

**问题**：生产 `POST /v1/orders` 频繁 500，Prisma 报 `prisma.order.create()` → "The provided value for the column is too long for the column's type. Column: image"。

**根因**：`OrderItem.image`（`String?` → 默认 VARCHAR(191)）存的是 `good.images[0].url` 的副本，而 `GoodImage.url` 早在 `20260802000000_url_to_text` 迁移已改为 LONGTEXT（COS 签名/长路径 URL 超过 191 字符）。该迁移漏改了 `OrderItem.image`，导致下单写 OrderItem 时值超长，整单回滚 500。

**修复**：
- `schema.prisma`：`OrderItem.image` → `String? @db.Text`
- 新增迁移 `20260802170000_order_item_image_to_text/migration.sql`：`ALTER TABLE OrderItem MODIFY COLUMN image LONGTEXT`
- 部署后 `start.sh` 的 `npx prisma migrate deploy` 自动应用

**潜在风险（暂未改，待观察）**：`User.avatar`、`Category.icon` 仍是 VARCHAR(191)；若后续存 COS 长 URL 也可能超长，到时一并改。

## 结算管理接口改造

**问题**：`vshop-server/src/modules/admin/admin.service.ts` 的 `getSettlement(supplierId)` 方法返回的是写死的假数据：
- `totalRevenue/pendingSettlement/settledAmount` 都是固定数字
- `thisMonth` 字段名是前端不识别的，导致「本月概况」显示订单数=0、金额=¥0.00
- `records` 也只有 2 条假数据

**修复**：按真实订单统计，业务语义定义：
- 已收入 = 所有 `payment.status='paid'` 订单的 payAmount 合计
- 已结算 = 已支付 且 订单 `status='done'` 的 payAmount 合计
- 待结算 = 已收入 - 已结算
- 本月概况 = 按 createdAt 落在当月 [monthStart, monthEnd) 的已支付订单统计订单数 + 金额
- 结算记录 list = 按自然月分组聚合（最近 12 个月），status 返回中文 '已结算'/'待结算'（与前端 `statusBadge` 的 badge 颜色映射匹配），settleTime 取该月订单最大 updatedAt

**返回字段**（前端 `public/index.html:2564-2573` 期望）：
```ts
{
  totalRevenue, pendingSettlement, settledAmount,  // 元
  monthlyOrders, monthlyAmount,                    // 月度统计
  list: [{ period, orderCount, amount, status, settleTime }, ...]
}
```

**关键点**：
- supplier 维度聚合：`where: { payment: { status: 'paid' }, supplierId }`；supplierId 为空时查全量（便于超管看全局）
- 金额 `payAmount` 库内是「分」，输出前端用 `centToYuan` 转「元」
- 前端 `statusBadge()` 的 badge 颜色映射只识别中文状态，所以后端直接返回 '已结算'/'待结算'，不要返回 'settled'/'pending'

## 订单发货功能修复（状态语义错位）

**问题**：用户反馈"订单管理需要增加发货功能"，实际是前后端状态语义错位导致发货按钮显示在错误订单上，已支付订单看不到发货入口。

**根因**：后端订单状态机（`payment.service.ts:83` 注释明确"待发货 pending→shipping"）：
- `pending` = 待付款（下单未支付）
- `shipping` = 待发货（已支付，等供应商发货）← 发货按钮应该在这里
- `receiving` = 待收货（已发货）
- `done` = 已完成

但 admin 后台 `public/index.html` 把状态搞反了：
- `statusBadge`：`shipping` 显示成"已发货"（应为"待发货"）、`receiving` 显示成"运输中"（应为"待收货"）
- `renderOrders`：发货按钮条件写成 `if (o.status === 'pending')`（应改为 `shipping`）→ 待付款订单显示发货按钮、已支付待发货订单反而没按钮
- filter tab：`data-filter="pending"` 标签"待发货"（应改为 `shipping`）

小程序端 `miniprogram/pages/order/list.js` 状态映射本来就是对的，只有 admin 后台错了。

**修复**（仅 `vshop-server/public/index.html`，4 处）：
1. `statusBadge` (1205行)：修正状态文本+颜色映射，颜色层次 灰(待付款)→橙(待发货)→蓝(待收货)→绿(已完成)→红(已取消)
2. filter tab (542行)：`data-filter="shipping"` 标签"待发货"，新增 `data-filter="pending"` "待付款" tab
3. `renderOrders` (2054行)：发货按钮从 `pending` 移到 `shipping`；`pending` 仅保留取消按钮，`shipping` 有发货+取消
4. 发货弹窗增强 (894行+2505行)：弹窗顶部展示订单号/收货人/商品数/金额，`openShipModal` 从 `orders` 数组取数据填充 `#shipOrderInfo`

**后端无需改动**：`updateOrderStatus`（admin.service.ts:664）已完整支持发货（接收 status/expressNo/expressCompany，更新 OrderPackage 包裹状态为 2 已发货，订单置为 receiving）。

**订单状态语义约定（重要，勿改）**：
- pending=待付款 shipping=待发货 receiving=待收货 done=已完成 cancelled=已取消
- 支付成功回调：payment.status→paid + order.status: pending→shipping（payment.service.ts:84）
- 发货：order.status: shipping→receiving，包裹 status=2（admin.service.ts:675）
- 确认收货：order.status: receiving→done，包裹 status=5（order.service.ts:592）

## 订单查询时间范围 + 批量导出 CSV

**需求**：订单管理增加按时间范围查询 + 批量导出订单。

**后端改动**（`admin.service.ts` + `admin.controller.ts`）：
- 抽取 `buildOrderWhere(supplierId, { status, keyword, startDate, endDate })` 私有方法，getOrders 和 exportOrdersCsv 共用
- `getOrders` 增加 startDate/endDate 参数，按 createdAt 区间过滤 `[startDate, endDate+1day)`（endDate 传当天自动包含整天）
- 新增 `exportOrdersCsv(supplierId, params)` 返回 `{ filename, csv, count }`：
  - 全量查询（不分页），include packages 取快递信息
  - CSV 带 BOM（\uFEFF）让 Excel 正确识别 UTF-8 中文
  - 字段：订单号/状态/收货人/手机号/商品数/商品总额/实付金额/创建时间/快递公司/快递单号/店管家同步
  - 标准 CSV 转义（含逗号/引号/换行的字段用双引号包裹，内部引号转义为两个双引号）
  - 文件名 `orders_YYYYMMDD_HHMM.csv`
- controller 新增 `@Get('orders/export')`：用 `@Res()` 手动返回 CSV 流，设置 `Content-Type: text/csv; charset=utf-8` + `Content-Disposition`（含 RFC 5987 编码的中文文件名）
- **路由顺序关键**：`@Get('orders/export')` 必须在 `@Get('orders/:id')` 之前定义，否则 'export' 会被当成 :id 参数

**前端改动**（`public/index.html`）：
- 筛选栏新增日期范围选择器（两个 `<input type="date">`）+ "清空日期" + "导出CSV" 按钮
- `loadOrders()` 读取 orderStartDate/orderEndDate 加到 query string
- 新增 `exportOrdersCsv()`：用 fetch 带 Authorization 头获取 Blob（window.open 无法带 JWT），从 Content-Disposition 解析文件名，用 `<a download>` 触发下载
- 新增 `clearOrderDateRange()`：清空日期并重新查询
- 切换状态 tab 时日期筛选自动保留（filterOrders 调 loadOrders，input 值不清空）

**导出接口鉴权**：用 AdminAuthGuard，前端 fetch 带 `authHeaders()`（Authorization: Bearer <token>）。不能用 window.open 或 `<a href>` 直接下载（无法带 JWT header）。

## 商品卡片占位图（goods-card 组件）

**问题**：用户反馈"小程序商品布局错乱"，截图显示第一个商品"正宗平和琯溪蜜柚"图片区域是空白（其他商品都是狗图）。根因不是布局代码（2列网格/子分类分组/tab栏均正确），而是 `goods-card` 组件在图片缺失或加载失败时没有占位显示，空白卡片让整体视觉看起来不整齐。

**修复**（`miniprogram/components/goods-card/`，3 文件）：
- `goods-card.wxml`：`<image>` 加 `wx:if="{{resolved.image}}"` 条件渲染 + `binderror="onImgError"`；加占位 div，`wx:if="{{!resolved.image || imgError}}"` 时显示 🛒 emoji
- `goods-card.js`：data 加 `imgError: false` 状态；observer 切换 item 时重置 imgError（避免上一张图失败状态残留）；methods 加 `onImgError()` setData imgError=true
- `goods-card.wxss`：`.c-card-img-hidden`（display:none 隐藏失败 image）；`.c-card-placeholder`（占位容器，背景色 rgba(255,255,255,0.35) 兜底防止 emoji 字体缺失时出现透明空洞）；`.c-card-placeholder-emoji`（font-size:72rpx opacity:0.5 line-height:1 防基线偏移）

**修复效果**：无图商品显示 🛒 占位；图片加载失败自动切占位；切换 item 重置 imgError。
