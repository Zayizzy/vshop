# 2026-07-28

## 诊断：商品保存 500（supplierId 外键违反）
- 现象：`PUT /api/admin/goods/:id` 500，`Foreign key constraint violated: supplierId`，`prisma.goodSupplier.create()` 失败
- 根因：admin 后台前端 `vshop-server/public/index.html:922` `const SUPPLIER_ID = 's1'` 硬编码
  - 所有请求带 `x-supplier-id: 's1'`
  - 后端 `admin.controller.ts` 每个方法 `supplierId = headers['x-supplier-id'] || 's1'`
  - `'s1'` 是 `prisma/seed.ts:27` 的开发种子数据（鲜果园旗舰店）
  - 生产云托管 MySQL 只跑 `migrate deploy` 不跑 `db seed`，Supplier 表无 `id='s1'` → 外键违反
- 触发点：`admin.service.ts:380` `updateGood` 编辑商品新增 sku 时 `goodSupplier.create({ supplierId: 's1' })`
- 影响：商品保存失败 → 上传的图片没绑定到商品 → 前端"没有图片"（与 COS 漏图叠加）
- 修复方向：
  - A（最快临时）：生产 MySQL `INSERT INTO Supplier (id,name,status,createdAt) VALUES ('s1','鲜果园旗舰店','active',NOW())`
  - B（前端）：`index.html` SUPPLIER_ID 改为登录后从后端取真实 supplierId 存 localStorage
  - C（后端根治）：admin 接口加 JWT 鉴权，从 token 取 supplierId，去掉 `|| 's1'` fallback

## 修复（采用 C 方案，2026-07-28）
- 新建 `common/guards/admin-auth.guard.ts`（AdminAuthGuard）：验证后台 JWT（payload `{supplierId,role,name}`）+ 校验 Supplier 存在，挂 req.user
- `admin.service.login` 注入 JwtService，签发真 JWT；查 Supplier 表确定 supplierId（传入校验或取第一个 active），去掉伪 token + 硬编码 `supplier:{id:'s1'}`
- `admin.controller.ts` 所有非 login 方法加 `@UseGuards(AdminAuthGuard)`，从 `(req as any).user.supplierId` 取，去掉 `headers['x-supplier-id']||'s1'`；KOC 方法 role 从 `req.user.role` 取
- `admin.module.ts` 注册 `AdminAuthGuard` provider（@UseGuards 运行时 DI 需要）
- `AdminLoginDto` 加可选 `supplierId`
- 前端 `index.html` `authHeaders/uploadHeaders` 去 `x-supplier-id`/`x-admin-role`，login fetch 去 header，只带 `Authorization`
- nest build 通过。生产无需插 's1' 数据，登录后自动绑定真实供应商
